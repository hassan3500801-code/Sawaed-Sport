# إصلاحات سواعد

## ما الذي تم إصلاحه؟

1. **المباراة القادمة:** أصبح التطبيق يدمج المباريات المحفوظة محليًا مع المباريات القادمة من Supabase بدل إخفاء البيانات المحلية عند اتصال التطبيق بقاعدة بيانات فارغة أو عند تعذر تحميل البيانات مؤقتًا. كما يتحقق من صحة تاريخ المباراة ويتجاهل السجلات ذات التاريخ غير الصحيح أو الحالة `finished` عند اختيار المباراة القادمة.
2. **إنشاء البطولة:** أُضيف جدول `public.match_scorers` مع علاقاته وسياسات الأمان والفهارس، وأضيفت أعمدة حالة المباراة إلى `matches` و`fixtures`. كما يطلب ملف SQL من PostgREST إعادة تحميل مخطط قاعدة البيانات بعد إنشاء الجدول، لمعالجة رسالة `Could not find the table 'public.match_scorers' in the schema cache`.
3. تم الحفاظ على `config.js` كما هو دون تغيير بيانات اتصال المشروع.

## خطوات التثبيت المهمة

1. احتفظ بنسخة احتياطية من ملفات موقعك الحالية.
2. ارفع واستبدل ملفات الحزمة في مجلد موقع GitHub Pages، مع إبقاء `config.js` الخاص بمشروعك إذا كان يحتوي على بيانات الاتصال الصحيحة.
3. افتح لوحة Supabase الخاصة بالمشروع نفسه.
4. افتح **SQL Editor** ثم انسخ محتوى `FIX_SAWAED_ERRORS.sql` ونفّذه مرة واحدة.
5. انتظر نجاح التنفيذ، ثم افتح الموقع وأجرِ تحديثًا كاملًا للصفحة أو امسح ذاكرة التخزين المؤقت للمتصفح.

> لا يكفي رفع ملفات JavaScript وحدها لحل رسالة الجدول المفقود؛ يجب تنفيذ ملف SQL على قاعدة البيانات التي يتصل بها الموقع. لا تنفّذ ملف SQL على مشروع Supabase مختلف.

## الاختبار

- أضف مباراة بتاريخ مستقبلي من حساب مشرف، ثم تحقق من ظهورها في بطاقة «المباراة القادمة» والصفحة الرئيسية.
- أنشئ بطولة جديدة من حساب مشرف. إذا استمرت رسالة schema cache، انتظر قليلًا ثم أعد تحميل الصفحة؛ وتأكد أن ملف SQL نُفّذ على المشروع الصحيح.
- راجع Console في أدوات المطور إذا لم تظهر المباراة؛ أصبح خطأ تحميل fixtures يظهر في Console بدل إخفائه بصمت.

## حدود التحقق

تم فحص صياغة `script.js` و`backend.js` باستخدام `node --check`. لم يتم الاتصال بقاعدة Supabase الفعلية أو تنفيذ SQL نيابةً عنك؛ لذلك يلزم تنفيذ خطوة SQL والاختبار على مشروعك.
